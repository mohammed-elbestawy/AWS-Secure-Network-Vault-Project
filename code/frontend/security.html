Security design

The service is built so that a breach of the server or the database does not expose any secret.

The link

https://host/view.html?id=ID#KEY

  • ID is 192 random bits. It selects the encrypted record. It cannot decrypt anything.
  • KEY is a fresh 256-bit AES key. It sits after the #, which browsers never send in a request.

What the server stores

  • The ciphertext (IV + AES-256-GCM output), padded to 256-byte blocks so its size hides the exact length.
  • An expiry time and a view counter.

What the server never has

  • The key, the plaintext, or any account or identity.
  • Full secret IDs in its logs. Only the first six characters are written.

Reading

Opening a link is a two-step flow. The page first asks whether the secret exists, which does not use a view. A view is consumed only when you press the button, so link previews and crawlers cannot burn a secret. The read and the delete happen in one database transaction, so two people opening the same link at the same moment cannot both succeed.

Limits you should know about

  • Anyone holding the full link can read the secret once. Send it over a channel you trust.
  • If your device or browser is compromised, the secret can be read there. Encryption does not help against that.
  • The page is served by the site, so you trust the site's code. Review the source before relying on it for high-value secrets.
  • There is no passphrase option yet.
